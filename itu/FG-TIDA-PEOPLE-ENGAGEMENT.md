## 二、逐步接触路径（Phased engagement，克制推进）

```
Phase 0 · 观察周（1-2 周）            ——只进不出
  订阅邮件列表 fgtida@lists.itu.int
  浏览 github.com/FG-TIDA 组织：现有 issue/讨论/工作仓
  浏览 tida.community：支持者名录、社区平台
  → 记录他们正在讨论什么，找到我们强相关的议题
Phase 1 · 首触（第 2-3 周）           ——一次一个动作
  在 FG-TIDA GitHub 上与"我们的强相关议题"互动：
  对一条现有 issue 回一条简短、建设性评论（附 1 个开源证据链接，不甩材料）
  → 目标：被看见、被当作"懂行的人"，而非推销者
Phase 2 · 单一贡献（第 3-4 周）       ——只交 1 份
  正式渠道：邮件秘书处 tsbfgtida@itu.int 登记支持者
  附**仅 1 份**贡献（推荐 C2 评估准则——Sounil 领域；说明"可应需展开"）
  → 目标：建立"我们真有货、且克制"的第一印象
Phase 3 · 会议互动（11-30/12-01 巴黎）——基于讨论再带出
  登记在线参会（必填）；进评估/信任生命周期对应 WG
  基于会上讨论，再带出 C1（信任生命周期）或 C5（开源差距）
  → 目标：从"提交文件"升级为"参与共建"
```

**节奏红线**：每周最多 1 次对外动作；先回应、后发起；每次只带一个主题；每份材料都有证据可复现；不重复提交、不以多取胜——正是"铺太大被关"教训的镜像。

## 三、"从哪个开始"的答案

1. **先订阅 + 看 FG-TIDA GitHub**（Phase 0）——他们的工作公开在 GitHub，我们能直接看到他们在讨论什么；
2. **首触对象**：优先在 GitHub 上与评估/安全类议题互动（Sounil 领域）；正式邮件联络按 **秘书处 → 全组** 走，不必一开始就点对点找 Chair（避免冒犯）；
3. **首批只给 1 份贡献**：C2（评估准则基准）——领域契合度最高（Sounil/Amir 双高）、无理论竞争性、现成完整；
4. C1（信任生命周期）留到会议/讨论需要时再出——它是我们的理论主场，值得"等到对的时机"。

## 四、我们的"GitHub 原生"优势（对 FG-TIDA 的展示面）

- FG-TIDA 在 GitHub 上工作 → 我们本身就是"开源+评测+AI 友好文档"的实践者（109 仓、llms.txt、AGENTS.md、扫描器）；
- 支持者姿态下，我们最自然的贡献是：**帮他们做证据/评测类工作**（差距分析、基准、可复现样例），而不是教育他们；
- 每次互动都留"证据可复现"的钩子（仓库链接/DOI），让接触逐步加深。
